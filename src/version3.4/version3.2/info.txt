================================================================================
     VERSION 3.2: MICROCODED FSM CONTROL SEQUENCER (cpu/micro-sequencer.js)
================================================================================

1. OVERVIEW & PURPOSE
---------------------
Version 3.2 replaces ad-hoc software control logic with the industry-standard
hardware control mechanism:
`cpu/micro-sequencer.js`.

In Version 3.1, while instructions were executed over multiple physical clock
cycles, the micro-operations were driven by a hardcoded JavaScript `switch(this.microStep)`
statement.

In real computer hardware:
  • Control signals are NOT generated by random ad-hoc software code.
  • The Control Unit is built as a **Microcoded Finite State Machine (FSM)**.
  • It contains a miniature ROM memory called the **Control Store ROM**.
  • The address of the active micro-instruction in ROM is held in a hardware
    register called the **Micro-Program Counter ($\mu\text{PC}$)**.
  • On every clock tick:
    1. The micro-instruction at ROM[$\mu\text{PC}$] is read out.
    2. Its control bits directly activate datapath bus gates (`Gate*`), register
       load enables (`LD_*`), memory strobes (`MemRead`), and ALU operations.
    3. The Micro-Sequencer logic evaluates the next-state condition field (`cond`)
       and instruction opcode to compute the next $\mu\text{PC}$ for the next clock tick!

Version 3.2 implements the textbook LC-3 microcode specification (Patt & Patel),
utilizing standard hardware state assignments (States 18, 33, 35, 32, 1, 2, 25).

3. THE CONTROL STORE ROM IN DETAIL (`cpu/micro-sequencer.js`)
================================================================================

Each micro-instruction word in the Control Store ROM contains:
  • `signals`: Bit-vector of active datapath gates and load enables.
  • `cond`   : Next-state condition (`UNCONDITIONAL` or `BRANCH_OPCODE`).
  • `nextState`: Default target $\mu\text{PC}$ state.
  • `opcodeMap`: Target state mapping when branching on opcode.

--------------------------------------------------------------------------------
LC-3 Standard State Map:
--------------------------------------------------------------------------------
State 18: FETCH-1
  • Control Signals: `GatePC = 1, LD_MAR = 1, MemRead = 1`
  • Action         : PC drives Central Bus -> MAR latches address -> MemRead asserted
  • Condition      : `COND.UNCONDITIONAL` -> Next $\mu\text{PC}$ = 33

State 33: FETCH-2
  • Control Signals: `LD_MDR = 1, MemRead = 1`
  • Action         : External memory bus read completes -> MDR latches instruction word
  • Condition      : `COND.UNCONDITIONAL` -> Next $\mu\text{PC}$ = 35

State 35: FETCH-3
  • Control Signals: `GateMDR = 1, LD_IR = 1`
  • Action         : MDR drives Central Bus -> IR latches instruction -> PC incremented
  • Condition      : `COND.UNCONDITIONAL` -> Next $\mu\text{PC}$ = 32

State 32: DECODE
  • Control Signals: Register File Read Ports A & B active, SEXT sign-extends
  • Action         : Micro-sequencer branches based on `IR[15:12]` (Opcode):
                     - Opcode 0b0001 (ADD) -> Next $\mu\text{PC}$ = **State 1**
                     - Opcode 0b0010 (LD)  -> Next $\mu\text{PC}$ = **State 2**
  • Condition      : `COND.BRANCH_OPCODE`

State 1 : ADD EXECUTE & WRITE-BACK
  • Control Signals: `GateALU = 1, LD_REG = 1, LD_CC = 1, ALUOp = 'ADD'`
  • Action         : ALU computes addition -> GateALU drives Central Bus ->
                     Register File captures into R[DR] -> PSR captures flags
  • Condition      : `COND.UNCONDITIONAL` -> Next $\mu\text{PC}$ = **18** (Instruction Complete!)

State 2 : LD ADDRESS CALCULATION
  • Control Signals: `GateMARMUX = 1, LD_MAR = 1, MemRead = 1, ALUOp = 'ADD'`
  • Action         : Address Adder computes `PC + SEXT9(offset9)` ->
                     GateMARMUX drives Central Bus -> MAR latches address -> MemRead asserted
  • Condition      : `COND.UNCONDITIONAL` -> Next $\mu\text{PC}$ = **25**

State 25: LD MEMORY READ & WRITE-BACK
  • Control Signals: `GateMDR = 1, LD_REG = 1, LD_CC = 1, MemRead = 1`
  • Action         : Memory read completes -> MDR captures data -> GateMDR drives Central Bus ->
                     Register File captures into R[DR] -> PSR captures flags
  • Condition      : `COND.UNCONDITIONAL` -> Next $\mu\text{PC}$ = **18** (Instruction Complete!)

================================================================================
5. SUMMARY & ARCHITECTURAL BENEFITS OF VERSION 3.2
================================================================================

1. Authentic Silicon Control Architecture:
   Control signals are emitted directly from micro-instruction words stored in the
   Control Store ROM, exactly as designed in classical CISC and RISC microprocessors.

2. True Micro-Branching:
   Instruction decoding is implemented as a physical micro-branch operation based
   on opcode bits, avoiding ad-hoc software switch statements.

3. Complete Terminal Visibility:
   Every executed instruction displays its exact $\mu\text{PC}$ state path
   (e.g., `Microcode FSM State Sequence : 18 -> 33 -> 35 -> 32 -> 1`), giving the user
   complete insight into the internal microcode engine.
